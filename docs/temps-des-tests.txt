Temps des tests de PÉPIN (carte 9.23, tri des tests), mesurés le 2026-11-18
==========================================================================

Mesure : chaque test lancé dans le conteneur de `docker-cargo.sh`, via `lourd.sh`,
avec la durée de chaque test donnée par libtest :
  RUSTC_BOOTSTRAP=1 ./docker-cargo.sh test -p core --release -- -Z unstable-options --report-time --format json
  RUSTC_BOOTSTRAP=1 ./docker-cargo.sh test -p game --release --no-default-features -- -Z unstable-options --report-time --format json
(APRÈS : les comptes rendus de `./docker-cargo.sh lot`, qui passe `--report-time` lui-même.)
Seuls les tests de plus de 2 s sont listés, du plus lent au moins lent.

À lire avec prudence : la machine (20 cœurs) était chargée par les autres cartes
(charge 10 à 65). Un test lancé seul va bien plus vite (essai « eau 2 » : 117 s
dans la suite AVANT, 25 s seul). Ce qui compte : l'ordre des tests et le chrono réel.

Ce que la carte a changé (détail dans QA.md, section « Carte 9.23 ») :
- `durees_plausibles` supprimé : il refaisait la recherche complète de chaque
  niveau ; ses vérifications passent dans `niveau_<n>_faisable` (même recherche).
- `reprise_depuis_chaque_lanterne` coupé en un test par niveau
  (`niveau_<n>_reprise`, `monde_2_niveau_<n>_reprise`) + un pour les niveaux
  d'essai : ils tournent en parallèle.
- Recherche arrêtée dès l'arrivée (`Options::arrivee_seule`) quand seule l'arrivée
  compte : reprises, robot maladroit, nouvelle partie +, marches de la mer...
- Nouvelle partie + : les niveaux qu'elle ne change pas (le Monde 2) ne sont plus
  refaits (déjà vérifiés par `zones`).
- Robot de QA : un parcours n'est cherché qu'UNE fois par processus (clocher,
  arc-en-ciel, Grand Nuage, horloge : deux tests chacun) ; mémoire sur disque par
  empreinte (code de la simulation + données du niveau), rejouée avant usage.
- Tests lents (> 5 s) en `#[ignore = "lot : ..."]` : lancés par `./docker-cargo.sh lot`.
- Profil `tests-rapides` (optimisation 3, sans LTO) au lieu de `--release`
  (taille minimale `z`, LTO) : essai « eau 2 » seul 25 s -> 18 s, compilation 22 s -> 13 s.

Chronos réels APRÈS (via lourd.sh) :
- `./docker-cargo.sh carte <clé>` (sans robot) : caniveau 17 s (recompilation comprise),
  égouts 14 s, clocher 19 s, marché 58 s ;
- `./docker-cargo.sh carte <clé> robot sans-memoire` (robot du niveau, sur demande) :
  caniveau 10 s, égouts 24 min 50 s (la recherche du robot des égouts) ;
- `./docker-cargo.sh lot` : 2 min 01 s, mémoire des parcours pleine (extraction propre) ;
  34 min 14 s, mémoire vide (toutes les recherches du robot refaites).
